# 学习通自动刷课脚本 V3 稳定版

当前版本以 `v3_optimized.js` 为唯一源码，油猴版由构建脚本生成。它聚焦于稳定播放与课程导航：

- 自动播放视频
- 视频自然结束后等待平台完成确认，再切换下一目录节点
- 识别章末测验；仅在前置完成与下一章节明确时跨章，测验保持未完成，否则安全停止
- 从“学习目标”步骤自动切到“视频”步骤
- 手动点“2视频”页签后自动重新接管播放

这版的目标是保持原模板的行为方式，不再额外叠加复杂的后台保活、通知、测试按钮等附加层，尽量减少冲突。

## DeepSeek 控制台练习版

仓库新增了独立的 [DeepSeek 控制台版](deepseek-console/README.md)，通过本地服务调用 DeepSeek API，识别章节练习题并辅助作答。原有 V3 脚本入口保持不变。

## 当前脚本行为

### 1. 学习目标页

如果当前小节先进入的是“学习目标”而不是视频页，脚本会尝试点击顶部的 `2视频` / `视频` 标签进入视频步骤。

说明：
- 这条路径已经按当前页面结构收紧，只走顶部视频标签，不再点击底部 `下一节` 按钮
- 原因是底部按钮在当前页面里可能触发额外调试/暂停逻辑，稳定性较差

### 2. 视频页

进入视频页后，脚本会：

- 识别 iframe 内的真实视频元素
- 自动调用 `play()`
- 如果播放被短暂中断，则尝试恢复播放
- 如果普通播放失败，则尝试静音播放

当前默认配置：

```javascript
configs: {
    playbackRate: 1.0,
    autoplay: true,
    retryInterval: 2000,
    maxRetries: 10,
    videoCheckInterval: 1000,
    autoAdvanceNoVideo: false,
    randomCooldownEnabled: true,
    randomCooldownMinMs: 5000,
    randomCooldownMaxMs: 12000,
}
```

### 3. 视频结束后

视频自然结束后，脚本先处理已识别的其余视频，再等待当前目录节点的 `.icon_Completed` 标记；正数待完成计数或不明确状态会阻止导航。该标记只作为页面可观察信号，不代表已独立验证服务端记录。未观察到确认时会有界重试并停止。

目录导航完成条件满足且存在合格的下一节点后，默认随机等待 5000–12000 毫秒（含两端），每次独立抽取整数毫秒并记录三位小数秒数，例如 `9.684s`。这仅用于稳定性和操作限频，不保证绕过平台检测。不会暂停正在播放的视频，也不会给同一内容页内尚待播放的视频插入随机停顿。

可通过 `app.configs.randomCooldownEnabled` 开关以及 `randomCooldownMinMs` / `randomCooldownMaxMs` 设置范围。范围须为非负整数毫秒，最大值不超过 2147483647；无效范围会安全停止。等待结束会重新确认任务、完成状态、页面和导航目标；页面变化、手动操作或任务失效会取消等待。浏览器可能延后实际回调时间，1 毫秒指抽样粒度。

### 4. 章节测验

仅对已观察到的“章节测验”与“本章自测”标签，在同章前置学习条件已满足、剩余节点均为章末测验且下一章节入口明确时，经冷却进入下一章。不会答题、提交或修改测验完成状态。验证、认证、登录提示、不可访问内容及结构不明确时停止；不会把强制验证当作可略过测验。

V3.4.0 固定使用 1.0x；保留 `app.configs.playbackRate` 属性，但赋值不会启用其他倍速。以上定制需在登录后的真实课程页面手动验证。

### 5. 文档与跨窗口直播基础设施

文档处理支持从起点逐步滚动到可验证底部，步长和间隔可变；只记本地处理完成，不要求额外的文档服务端轮询。混合视频或直播任务仍保留相应平台完成确认。

跨窗口状态 `WAITING_LIVE` 在打开窗口前设置。协议仅支持严格同源、保留 opener 的普通 `_blank` 链接；有限时长回放可报告 99% 本地进度，无限或未知时长不按经过时间判完成。仅关闭关联子窗口，确认关闭与必要完成条件后才开始现有导航冷却。

**真实文档/直播适配器默认不注册（`app.taskAdapter === null`）**：尚无真实查看器、直播入口与播放器 DOM 证据，不能宣称开箱即用。子页还需要经过验证的 URL 匹配和播放器适配器；本次不扩展 `@match` 或 `@grant none`。接口、合成双窗口测试和限制见 [NAVIGATION_REVIEW.md](NAVIGATION_REVIEW.md)。

## 使用方法

### 方法一：控制台执行

1. 打开学习通课程播放页
2. 按 `F12`
3. 进入 `Console`
4. 复制 [v3_optimized.js](v3_optimized.js) 全部内容
5. 粘贴并执行

首次执行后可用：

```javascript
app.run()
app.nextUnit()
```

### 方法二：Tampermonkey

1. 安装 Tampermonkey
2. 导入 [v3_optimized.user.js](v3_optimized.user.js)
3. 确认脚本已启用
4. 刷新学习通播放页面

## 已知说明

### 0. 无视频或课件页面

不会自动跳过无法识别的无视频页面。`autoAdvanceNoVideo` 属性保留兼容，但不再允许绕过未知内容；`app.nextUnit()` 也需要协调器确认完成。请手动处理后执行 `app.run()`。

### 1. 为什么有时会看到 `AbortError`

常见报错：

```text
The play() request was interrupted by a call to pause()
```

这通常不是视频坏了，而是：

- 页面从步骤页切到视频页时，播放器初始化会短暂停一下
- 页面内部脚本会在加载过程中重置播放状态
- 浏览器对媒体播放请求进行了短暂中断

脚本会优先尝试恢复播放，而不是立即判定失败。

### 2. 为什么会出现重复日志

如果同一页面反复粘贴执行脚本，会导致同一套监听和定时逻辑叠加，从而出现多次日志。

建议：

- 刷新页面后只执行一次
- 如果使用油猴版，尽量不要再在控制台重复粘贴执行

### 3. 为什么“静音播放成功”但一开始还能听到声音

旧逻辑里曾经会在静音启动成功后恢复声音。当前建议使用持续静音方式，不再自动恢复。

## 当前调试结论

目前这版已经验证：

- 顶部 `2视频` 标签可以程序化点击
- 手动进入视频页后可以自动播放
- 静音恢复链路可用

目前重点保留的是稳定性，不再继续叠加额外功能。

## 维护与验证

修改 `v3_optimized.js` 后，执行：

```bash
node scripts/build-userscript.mjs
node tests/verify-v3.mjs
node tests/customization-v3.mjs
node tests/preserved-v3.mjs
```

第二条命令会验证两个入口的语法，并确认油猴脚本与唯一源码完全一致。Chrome DOM 回归测试的环境、命令及限制见 [NAVIGATION_REVIEW.md](NAVIGATION_REVIEW.md)。

保留：原有页面焦点保护、暂停恢复、卡顿检测、恢复冷却和静音回退。新增：动态目录叶节点发现、统一完成协调器、定时任务取消、1.0x 约束和状态确认。未支持：数字内容页签的自动切换、录播/音频专用适配器、不可访问的 iframe；遇到这些情况安全停止。
