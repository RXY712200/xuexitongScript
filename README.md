# 学习通自动刷课脚本 V3 稳定版

当前版本以 `v3_optimized.js` 为唯一源码，油猴版由构建脚本生成。它聚焦于稳定播放与课程导航：

- 自动播放视频
- 视频自然结束后等待平台完成确认，再切换下一目录节点
- 识别章末测验；仅在前置完成与下一章节明确时跨章，测验保持未完成，否则安全停止
- 从“学习目标”步骤自动切到“视频”步骤
- 手动点“2视频”页签后自动重新接管播放

这版的目标是保持原模板的行为方式，不再额外叠加复杂的后台保活、通知、测试按钮等附加层，尽量减少冲突。

## DeepSeek 控制台练习版

仓库新增了独立的 [DeepSeek 控制台版](deepseek-console/README.md)，通过本地服务调用 DeepSeek API，识别章节练习题并辅助作答。原有 V3 脚本入口保持不变。

## 当前脚本行为

### 1. 学习目标页

如果当前小节先进入的是“学习目标”而不是视频页，脚本会尝试点击顶部的 `2视频` / `视频` 标签进入视频步骤。

说明：
- 这条路径已经按当前页面结构收紧，只走顶部视频标签，不再点击底部 `下一节` 按钮
- 原因是底部按钮在当前页面里可能触发额外调试/暂停逻辑，稳定性较差

### 2. 视频页

进入视频页后，脚本会：

- 识别 iframe 内的真实视频元素
- 自动调用 `play()`
- 如果播放被短暂中断，则尝试恢复播放
- 如果普通播放失败，则尝试静音播放

当前默认配置：

```javascript
configs: {
    playbackRate: 1.0,
    autoplay: true,
    retryInterval: 2000,
    maxRetries: 10,
    videoCheckInterval: 1000,
    autoAdvanceNoVideo: false,
}
```

### 3. 视频结束后

视频自然结束后，脚本先处理已识别的其余视频，再等待当前目录节点的 `.icon_Completed` 标记；正数待完成计数或不明确状态会阻止导航。该标记只作为页面可观察信号，不代表已独立验证服务端记录。未观察到确认时会有界重试并停止。

合适的自动动作使用统一可取消调度器，默认按动作类型使用短延迟（见下表）。每次独立抽取包含两端的整数毫秒，日志以三位小数秒显示。章节、测验与直播返回不会叠加重复导航等待；暂停恢复、焦点恢复、卡顿检测、完成识别和安全检查不增加随机等待。这仅用于稳定性与操作限频，不保证绕过平台检测。

### 4. 章节测验

仅对已观察到的“章节测验”与“本章自测”标签，在同章前置学习条件已满足、剩余节点均为章末测验且下一章节入口明确时，经冷却进入下一章。不会答题、提交或修改测验完成状态。验证、认证、登录提示、不可访问内容及结构不明确时停止；不会把强制验证当作可略过测验。

V3.4.0 固定使用 1.0x；保留 `app.configs.playbackRate` 属性，但赋值不会启用其他倍速。以上定制需在登录后的真实课程页面手动验证。

### 5. 文档与跨窗口直播基础设施

文档处理支持从起点逐步滚动到可验证底部，步长和间隔可变；只记本地处理完成，不要求额外的文档服务端轮询。混合视频或直播任务仍保留相应平台完成确认。

跨窗口状态 `WAITING_LIVE` 在打开窗口前设置。协议仅支持严格同源、保留 opener 的普通 `_blank` 链接；有限时长回放可报告 99% 本地进度，无限或未知时长不按经过时间判完成。仅关闭关联子窗口，关闭与返回共享一次等待；确认关闭与必要完成条件后，不再叠加课节或章节等待。

**真实文档/直播适配器默认不注册（`app.taskAdapter === null`）**：尚无真实查看器、直播入口与播放器 DOM 证据，不能宣称开箱即用。子页还需要经过验证的 URL 匹配和播放器适配器；本次不扩展 `@match` 或 `@grant none`。接口、合成双窗口测试和限制见 [NAVIGATION_REVIEW.md](NAVIGATION_REVIEW.md)。

### 6. 中文设置面板

课程页右上角的“学习设置”可折叠。可独立控制自动播放、课内下一视频、下一课节、下一章节、测验交接、文档阅读、直播协调、后台播放保护及随机延迟总开关。每类延迟还有独立开关和最小/最大毫秒字段。

| 动作 | 默认范围（ms，含两端） |
| --- | --- |
| 视频开始 | 300–900 |
| 课内下一视频 | 500–1500 |
| 文档逐步滚动 | 400–1200 |
| 下一文档 | 500–1500 |
| 下一课节 | 1000–2500 |
| 下一章节 | 1500–3500 |
| 测验交接 | 1000–2500 |
| 打开直播窗口 | 500–1500 |
| 直播关闭与返回 | 500–1500 |

默认使用短预设；旧版长预设为各类动作 5000–12000ms，也可自定义。范围须为非负整数、最小值不超过最大值、最大值不超过 2147483647ms。关闭随机延迟不等于关闭自动化；文档逐步滚动即使零延迟也让出事件循环。

后台保护默认开启，文档/直播开关默认关闭且仍需经过验证的适配器。设置仅通过 `xuexitong.v3.action-settings.v1` 保存到当前来源的 localStorage，不保存账号、课程或进度信息；存储不可用时仅在本页生效。更改相关开关或范围会取消待执行动作，不会重启已完成任务或暂停正在正常播放的视频；必要时手动选择内容或执行 `app.run()` 重新识别。

`app.settings` / `app.updateSettings(...)` 为设置接口；`app.configs.autoplay` 和 `randomCooldownEnabled` 保留为对应开关别名。旧的 `randomCooldownMinMs/MaxMs` 仅用于旧版预设下的导航兼容，新设置以面板中的分类范围为准。浏览器限流可能延后回调，1ms 指抽样粒度，不保证墙钟精度。

## 使用方法

### 方法一：控制台执行

1. 打开学习通课程播放页
2. 按 `F12`
3. 进入 `Console`
4. 复制 [v3_optimized.js](v3_optimized.js) 全部内容
5. 粘贴并执行

首次执行后可用：

```javascript
app.run()
app.nextUnit()
```

### 方法二：Tampermonkey

1. 安装 Tampermonkey
2. 导入 [v3_optimized.user.js](v3_optimized.user.js)
3. 确认脚本已启用
4. 刷新学习通播放页面

## 已知说明

### 0. 无视频或课件页面

不会自动跳过无法识别的无视频页面。`autoAdvanceNoVideo` 属性保留兼容，但不再允许绕过未知内容；`app.nextUnit()` 也需要协调器确认完成。请手动处理后执行 `app.run()`。

### 1. 为什么有时会看到 `AbortError`

常见报错：

```text
The play() request was interrupted by a call to pause()
```

这通常不是视频坏了，而是：

- 页面从步骤页切到视频页时，播放器初始化会短暂停一下
- 页面内部脚本会在加载过程中重置播放状态
- 浏览器对媒体播放请求进行了短暂中断

脚本会优先尝试恢复播放，而不是立即判定失败。

### 2. 为什么会出现重复日志

如果同一页面反复粘贴执行脚本，会导致同一套监听和定时逻辑叠加，从而出现多次日志。

建议：

- 刷新页面后只执行一次
- 如果使用油猴版，尽量不要再在控制台重复粘贴执行

### 3. 为什么“静音播放成功”但一开始还能听到声音

旧逻辑里曾经会在静音启动成功后恢复声音。当前建议使用持续静音方式，不再自动恢复。

## 当前调试结论

目前这版已经验证：

- 顶部 `2视频` 标签可以程序化点击
- 手动进入视频页后可以自动播放
- 静音恢复链路可用

目前重点保留的是稳定性，不再继续叠加额外功能。

## 维护与验证

首次自动接管现在先等待活动目录、内容文档和播放器就绪，采用有上限且可取消的采样；不会循环执行 `app.run()`。等待期间切换任务、离开页面、关闭播放功能或销毁脚本会取消接管，超时后保留手动重新识别入口。手动 `app.run()` 仍执行完整安全检查。

复杂多分支课件不会按播放器数量、文档序号或“隐藏”属性自动猜测任务归属。现有三文档辅助音频例外保留；更复杂结构仅支持由显式适配器提供并持续验证的活动分支、非活动分支及辅助音频归属，且仍检查全部文档中的未知或不可访问内容。**真实 20 文档课件的活动归属尚无充分证据，默认仍会安全停止；合成测试中的分支标记不是平台适配器。** 可只读查看 `app._discoverMedia().reasons` 获取不含账号、URL 的阻断类别。详细测试与限制见审查报告末节。

本次审查分支新增了受限的直播回放弹窗适配：仅识别 `https://zhibo.chaoxing.com` 上已确认的“直播”标题、录播标志和 Video.js 结构。跨域通信仅允许 `https://mooc1.chaoxing.com` 课程页与该弹窗配对；回放须自然结束，父页仍须确认课程完成标记。不会把 99% 位置或“直播已结束”文字当成该录播完成。直播功能默认关闭，不能据此认定真实平台可无人值守运行。

新增真实入口结构识别：仅在唯一 `iframe#iframe[info="card"]` 中识别唯一 `a.liveHref > div.liveCard > div.live-ct`，只读检查平台动态创建或更新的 `#openUrl`。**未安装可选桥接时，该原生入口仅支持人工交接，不支持自动开窗返回。** 原平台处理器保持不变，脚本不会为获取 URL 而调用关系函数，不把 `javascript:void(0)` 当作回放地址，也不改写原生点击或安全策略。启用直播功能后，请手动点击原卡片。原生 `.click()` 不返回窗口引用，不会猜测归属或关闭弹窗。已有显式持有合法窗口引用的适配器仍保留原跨域协调流程。

可选伴随脚本：[xuexitong-live-bridge.user.js](xuexitong-live-bridge.user.js)。在 Tampermonkey 中单独安装，核心脚本仍为 `@grant none`。当前任务开始后有界发现伴随脚本：每 250ms 探测，最多 20 次或 5 秒，取消后不接受迟到响应；支持两种加载顺序。手动打开原生回放后，可按提示显式配对，保留真实 ended 和页面完成标记检查。**同页消息不能证明发送者来自伴随脚本，因此此桥接路径的自动续课已禁用，即使真实回放结束且用户确认关闭也须手动选择下一课节。** 不自动打开或关闭无主窗口；`pagehide` 不证明关闭，会话 ID 也不证明发送者身份。真实 Tampermonkey 与登录平台流程尚未验证，见 [UNIFIED_COMPATIBILITY_REVIEW.md](UNIFIED_COMPATIBILITY_REVIEW.md)。测试：`node tests/bridge-v3.mjs`。

“暂缓章节测验并继续学习”默认开启：只暂缓 `章节测验`、`章节测试`、`本章自测`，保持未完成状态，按目录顺序寻找后续学习项。认证、考试、锁定项或没有明确后续目标时停止，不答题、不提交。

新增回放回归命令为 `node tests/recorded-live-v3.mjs`，与 `node tests/navigation-v3.mjs` 使用同一 Playwright/Chrome 环境；全部结果及证据限制见审查报告末节。

原生入口回归命令为 `node tests/native-entry-v3.mjs`；其中关系函数只是测试桩，不代表已查明真实平台函数的内部行为。

修改 `v3_optimized.js` 后，执行：

```bash
node scripts/build-userscript.mjs
node tests/verify-v3.mjs
node tests/customization-v3.mjs
node tests/preserved-v3.mjs
```

第二条命令会验证两个入口的语法，并确认油猴脚本与唯一源码完全一致。Chrome DOM 回归测试的环境、命令及限制见 [NAVIGATION_REVIEW.md](NAVIGATION_REVIEW.md)。

保留：原有页面焦点保护、暂停恢复、卡顿检测、恢复冷却和静音回退。新增：按附件顺序播放视频、受限的 Video.js 音频识别、兼容旧设置的音频开关与延迟、侧栏课节切换生命周期。音频第二组件必须满足隐藏且非活动的结构约束，否则停止。PDF 附件保持待处理，文档关闭时暂停；缺少可靠内部视图时不自动滚动。原生回放的自动窗口归属/开关窗、未知音频结构和不可访问任务仍不支持。以上新增路径仍需真实登录环境复测。

定向兼容修复：`ans-attach-online ans-insertaudio` 现在会遍历内部文档后执行原有音频识别；尚未出现主播放器时有界等待。明确关联到唯一 Video.js 播放器的范围控件可通过，独立表单、无法证明归属的控件、object/embed/canvas 仍停止。`auditionAudio` 的严格条件未放宽，新增具体拒绝原因；本次真实诊断未包含全部属性，因此不猜测其失败条件。音频/视频混合附件仍不自动处理；多个纯音频附件按顺序处理。详见审查报告末节，本地合成测试不代表真实页面兼容。
